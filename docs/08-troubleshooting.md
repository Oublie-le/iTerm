# 故障排查

更新时间：2026-07-27  
适用版本：iTerm 0.x

## 1. 安装与启动

### macOS 提示应用无法验证

当前预览版没有 Apple 签名和公证。确认安装包来自项目
[Releases](https://github.com/Oublie-le/iTerm/releases) 后，可在“系统设置 → 隐私与安全性”
中选择仍要打开。不要通过关闭 Gatekeeper 的全局命令绕过系统保护。

### Windows 显示 SmartScreen

当前预览版没有商业代码签名。确认发布者来源和下载页面后，使用 SmartScreen 的详细信息
查看文件，再决定是否运行。正式发布前应配置 Windows 代码签名。

### Linux AppImage 无法启动

先授予执行权限：

```bash
chmod +x iTerm_*.AppImage
```

部分发行版还需要 FUSE 2 兼容包；也可改用对应的 `.deb`。桌面环境缺少 WebKitGTK 或
系统图形库时，优先使用发行版包管理器补齐 Tauri 运行依赖。

## 2. 串口

### 列表中没有设备

1. 点击会话管理器顶部的刷新按钮；
2. 确认数据线支持数据传输，而不只是充电；
3. 用系统工具确认设备存在：

   - macOS：`ls /dev/cu.*`
   - Linux：`ls /dev/ttyUSB* /dev/ttyACM*`
   - Windows：设备管理器 → 端口（COM 和 LPT）

4. 检查 FTDI、CP210x 或 CH340/341 驱动；
5. 拔插设备后重新刷新。

浏览器 Mock 模式显示的是演示端口，只有 `pnpm tauri:dev` 或安装后的原生应用会访问真实
串口。

### Linux 报权限不足

常见发行版把串口分配给 `dialout` 组：

```bash
sudo usermod -aG dialout "$USER"
```

Arch Linux 等发行版可能使用 `uucp`。重新登录后用 `groups` 确认组权限。不要长期使用
`sudo` 启动 iTerm，也不要把设备节点设置为全局可写。

### 端口被占用

同一串口通常只能由一个进程独占。关闭 Arduino Serial Monitor、PlatformIO、ModemManager、
其他终端或旧的 iTerm 会话后重试。Linux 可用 `lsof /dev/ttyUSB0`，macOS 可用
`lsof /dev/cu.*` 定位占用者。

### 收到乱码

依次核对：

1. 波特率；
2. 数据位、校验位、停止位；
3. 硬件/软件流控；
4. 会话字符集；
5. 设备输出究竟是文本还是二进制。

不确定数据是否为文本时切换到 Hex 接收视图。若 Hex 字节正确而文本错误，问题通常是
字符集或终端控制序列，而不是线路参数。

### 能接收但不能发送

- 确认会话状态是“已连接”；
- 检查发送器是文本还是 Hex 模式；
- 核对 LF、CR、CRLF 行尾；
- 检查设备是否要求 RTS/CTS、DTR/DSR 或 XON/XOFF；
- 使用终端设置中的 Enter/Backspace 映射匹配目标设备。

### 拔插后无法重连

iTerm 会优先用 USB VID、PID 和序列号匹配同一设备，但没有序列号的转换器可能在重插后
得到不同端口。刷新设备，编辑会话并重新选择端口；同时确认旧会话或其他进程已释放句柄。

## 3. SSH

### 提示找不到 ssh

iTerm 调用系统 OpenSSH。先在终端执行：

```bash
ssh -V
```

macOS 和大多数 Linux 默认包含 OpenSSH；Windows 可在“可选功能”中安装 OpenSSH Client。
安装后完全退出并重新启动 iTerm，使应用获得最新的 `PATH`。

### 主机密钥校验失败

严格校验开启时，目标必须存在于 `known_hosts`，且密钥不能发生未确认变化。先在系统终端
直接运行同一 SSH 目标，核对指纹并修正 `known_hosts`。不要在不理解风险时删除全部
`known_hosts` 或长期关闭严格校验。

### 密钥或 Agent 认证失败

- 用 `ssh-add -l` 检查 Agent；
- 检查用户名、端口和私钥路径；
- 在系统终端使用同一参数连接，读取 OpenSSH 的详细错误；
- 私钥权限过宽时，OpenSSH 会拒绝使用该文件；
- “密码 / 键盘交互”模式的密码应直接输入终端提示，iTerm 不保存密码。

## 4. ADB

### 提示找不到 adb

安装 Android SDK Platform Tools，并在系统终端执行：

```bash
adb version
adb devices -l
```

如果终端可执行而 iTerm 不可执行，完全退出应用后重新打开，或把 Platform Tools 加入由
桌面应用可见的系统 `PATH`。

### 设备是 unauthorized

1. 解锁 Android 设备；
2. 确认已启用开发者选项和 USB 调试；
3. 接受设备上的 RSA 指纹提示；
4. 重新执行 `adb devices -l` 并刷新 iTerm。

没有出现提示时，可在设备开发者选项中撤销 USB 调试授权后重新连接。不要复制不可信
电脑生成的 ADB 密钥。

### 设备是 offline

先重新插拔数据线，再尝试：

```bash
adb kill-server
adb start-server
adb devices -l
```

该操作会影响本机所有使用 ADB 的程序。网络 ADB 还需检查设备 IP、端口、防火墙和配对
状态。

## 5. 日志与文件传输

### 日志没有写入

- 会话必须已连接，日志状态应显示“记录中”；
- 检查是否处于暂停状态；
- 点击“打开日志目录”确认实际目录；
- 检查磁盘空间和目录权限；
- 达到大小限制时会按配置轮转，旧文件可能已改名。

日志记录可能包含设备敏感信息。分享前检查内容，处理结束后按需删除。

### X/Y/ZModem 一直等待

- XModem/YModem 需要发送端和接收端使用同一协议；
- ZModem 发送通常等待远端运行 `rz`，接收通常等待远端运行 `sz`；
- 普通终端输入在传输期间会锁定，避免破坏协议字节流；
- 确认链路没有做换行转换、软件回显或字符集转换；
- 当前 ZModem 面向可靠链路，不提供噪声线路的完整错误纠正。

若目标是 Bootloader，先确认它实现的具体 X/YModem 变体、块大小和握手字符。

## 6. 配置与诊断

### 工作区恢复异常

先导出会话配置，关闭所有会话后重新启动。若问题仍存在：

1. 打开“应用设置 → 本地诊断”；
2. 导出诊断 JSON；
3. 检查导出说明和脱敏内容；
4. 清空诊断并复现一次。

诊断不包含终端收发内容和密码，但报告问题前仍应人工检查主机名、端口、系统错误消息等
环境信息。

### 完全重置

使用“应用设置 → 重置本地数据”可同时清空 SQLite、WebView Storage 和诊断，并恢复
默认设置。该操作会断开活动会话，但不会删除日志、接收文件或手动导出文件。

如果应用内重置失败，完整的手动步骤见
[数据与隐私说明](07-privacy.md#5-用户控制和删除)。仅删除 SQLite 文件不一定有效，因为
WebView Storage 中的旧配置可能在下次启动时重新迁移。

## 7. 报告问题

报告问题时建议附上：

- iTerm 版本和安装包类型；
- 操作系统版本与 CPU 架构；
- 会话协议；
- 串口转换器型号、VID/PID 和驱动版本（不要公开不必要的序列号）；
- 可复现步骤、预期结果和实际结果；
- 经人工检查的诊断导出；
- 是否能在系统 `ssh`、`adb` 或其他串口工具中复现。

不要在公开 Issue 中提交密码、令牌、私钥、完整终端日志、客户数据或未脱敏的配置导出。
