# 实施、测试与验收计划

文档状态：Draft
更新时间：2026-07-27

## 1. 实施原则

- 先冻结参考基线，再做视觉开发；
- 先验证串口数据链路，再搭完整界面；
- 原始字节正确性优先于渲染效果；
- 每个里程碑都必须产出可运行安装包；
- P0 偏差必须修复或由产品负责人书面接受；
- 不把 X/Y/ZModem、分屏等高风险模块塞进 MVP 关键路径。

## 2. 里程碑

工作量为单名熟练工程师的净工程日估算，不含等待硬件、签名账号和外部评审时间。

| 阶段 | 目标 | 主要产物 | 估算 |
| --- | --- | --- | --- |
| M0 基线冻结 | 明确“一比一”对象 | 截图库、页面清单、行为矩阵、ADR | 2–4 天 |
| M1 技术 Spike | 淘汰不可行架构 | 串口回环、Channel、xterm 性能报告 | 4–6 天 |
| M2 串口内核 | 可靠收发 | Driver、Actor、状态机、错误模型 | 5–8 天 |
| M3 MVP 工作区 | 可完成核心任务 | 主壳、会话编辑、多标签、终端、发送 | 7–10 天 |
| M4 v1.0 核心 | 达到日常可用 | 日志、Hex、时间戳、热插拔、布局恢复 | 7–10 天 |
| M5 高级对齐 | 补齐 WindTerm 串口体验 | 分屏、同步输入、触发器、X/Y/ZModem | 8–14 天 |
| M6 跨平台硬化 | 可发布 | 硬件矩阵、视觉收敛、安装包、文档 | 6–10 天 |

总量约 39–62 工程日。单人完整交付约 8–13 周；两人并行但保留串口内核单一负责人时，
约 5–8 个日历周。若 v1.0 不含 M5，可提前发布并在 v1.1 补齐。

## 4. 测试策略

### 4.1 测试金字塔

| 层级 | 内容 | 工具/方法 |
| --- | --- | --- |
| 单元 | 状态机、参数校验、增量解码、Hex 解析、行尾、CRC | Rust test、Vitest |
| 组件 | 会话表单、标签状态、发送器、错误条、主题 | Testing Library、Storybook |
| 集成 | Actor + Driver、SQLite、日志、Channel、背压 | Rust integration tests |
| E2E | 新建连接、收发、拔插、重连、布局恢复 | Playwright/WebDriver + 测试夹具 |
| 视觉 | 页面和交互状态截图 | Playwright screenshot + 人工复核 |
| 硬件 | 参数、流控、控制线、驱动差异、长稳 | 真实 USB 转串口矩阵 |
| 互操作 | X/Y/ZModem 与常见端实现互传 | lrzsz/设备 Bootloader/参考工具 |

### 4.2 自动化串口夹具

#### POSIX

- 使用 PTY 对模拟串口对；
- 一端由应用打开，另一端由测试程序注入和校验；
- 故障注入：关闭 peer、延迟、截断、突发大块、非法字节。

#### Windows

- CI/开发机使用受控虚拟串口对；
- 发布前必须用真实 COM 设备复验；
- 测试端口占用、设备编号变化和系统睡眠。

#### 硬件回环

- TX-RX 回环；
- RTS-CTS、DTR-DSR 在支持的适配器上回环；
- 逻辑分析仪抽检行尾、间隔和自定义波特率。

### 4.3 关键数据用例

- 所有 0x00–0xFF 字节往返；
- 1 字节到 64 KiB 随机块；
- UTF-8、GBK、Big5 字符在每个字节位置切块；
- 1 MB、100 MB 连续流；
- ANSI 颜色、光标移动、清屏、进度行；
- 10 MB 粘贴应被预览/限制，而非冻结 UI；
- 循环发送 10 ms 间隔持续 1 小时；
- 日志写满和目录被删除；
- UI 故意阻塞 2 秒仍保持 sequence 连续。

## 5. 视觉验收

### 5.1 Golden 场景

至少保存：

1. 空工作区；
2. 新建串口会话第一页和串口参数页；
3. 已连接终端；
4. 连接失败通知；
5. 设备丢失通知；
6. 发送窗格单次/循环状态；
7. Hex 视图；
8. 日志设置与记录中状态；
9. 多标签；
10. 横向/纵向分屏；
11. 深色/浅色主题。

### 5.2 差分规则

- 统一逻辑分辨率、缩放、语言、主题和测试字体；
- 遮罩系统标题栏、系统滚动条和时间；
- 几何误差优先修复，再调颜色和字体；
- 抗锯齿差异使用结构相似度与人工复核；
- P0 组件不接受“看起来差不多”作为验收。

## 6. 功能验收示例

### AC-01：创建并连接串口

给定系统存在一个可用 USB 串口，用户新建会话并选择 115200/8/N/1/None，点击连接后：

- 会话保存到会话树；
- 标签进入 Opening，成功后变为 Connected；
- 工具栏显示协议和端口；
- 键盘输入可在回环端收到；
- 关闭会话后端口句柄释放。

### AC-02：设备拔出

给定会话已连接，用户拔出设备：

- 1 秒内进入 DeviceLost；
- 标签和通知条同时显示断开；
- 输入和发送器禁用；
- 终端内容、发送内容和日志状态保留；
- 设备插回后用户可一键重连。

### AC-03：循环发送

给定有效 Hex `AA 55 01 0D 0A` 和 100 ms 间隔，开始发送 10 秒：

- 每帧原始字节完全一致；
- 间隔误差在平台计时能力允许范围内；
- 停止按钮在 100 ms 内生效；
- 无部分帧、重帧或静默写失败。

### AC-04：日志

给定“记录全部原始字节”，注入 0x00–0xFF：

- 文件内容与输入逐字节一致；
- 暂停期间不写入，继续后恢复；
- 日志失败会提示但连接保持；
- 停止日志后文件句柄释放。

## 7. 风险清单

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 百万行使 xterm.js 内存过高 | 高 | 高 | M1 压测；分层回滚/spool；必要时替换渲染器 |
| WebView 跨平台视觉差异 | 高 | 中 | 平台 Golden；统一字体/token；允许系统层遮罩 |
| 串口库平台能力不一致 | 中 | 高 | `SerialDriver` 隔离；平台测试；必要时原生适配器 |
| Windows 驱动/端口热插拔差异 | 高 | 高 | 真实设备矩阵；稳定设备键；明确错误 |
| 高频 IPC 造成 UI 卡顿 | 中 | 高 | 二进制 Channel、批处理、背压、直接写渲染器 |
| X/Y/ZModem 库不成熟 | 中 | 高 | 放到 P1；互操作测试；协议层独立 |
| 视觉复刻产生品牌/IP 风险 | 中 | 高 | clean-room、独立品牌和素材、发布前法律审核 |
| 日志泄露设备敏感信息 | 中 | 高 | 本地优先、默认关闭、诊断去敏、隐私说明 |
| 范围膨胀为完整 WindTerm | 高 | 高 | 坚持串口边界；新增协议走独立版本评审 |

## 8. 决策门

### Gate A：M0 后

确认参考版本、范围和视觉验收。未确认则只做通用 Spike，不进入高保真 UI。

### Gate B：M1 后

根据数据选择继续 xterm.js/serialport-rs，或切换终端/串口适配器。

### Gate C：M4 后

决定直接发布 v1.0，还是把 M5 的 X/Y/ZModem 和分屏纳入首发。

### Gate D：发布前

产品、工程、测试和合规共同签署发布检查表。
