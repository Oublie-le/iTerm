# 终端性能基线

## 目的

本基线用于持续观察 iTerm 所用 xterm.js 版本在大量终端输出下的解析吞吐、回滚保留、
全缓冲扫描和进程内存变化。10 万、50 万、100 万行分别在独立 Node.js 进程中运行，
避免前一轮的堆内存影响后一轮结果。

基准数据包含 UTF-8 中文、ANSI SGR 颜色序列和 CRLF。测试会在第一行写入唯一标记，
完成后从缓冲区末尾向前完整扫描，确认首行未被意外丢弃。

## 运行

轻量 CI 冒烟检查：

```bash
pnpm bench:terminal:smoke
```

完整矩阵：

```bash
pnpm bench:terminal
```

机器可读 JSON：

```bash
node scripts/benchmark-terminal.mjs --lines 100000,500000,1000000 --json
```

`--lines` 的单项上限为 100 万行。`--assert` 会检查首行保留、缓冲行数以及宽松的
60 秒解析、30 秒搜索上限，适合发现数量级退化，不作为不同 CI 主机之间的精确性能排名。

## 指标边界

这是一项不打开 DOM、Canvas 或 WebGL 渲染器的 xterm.js 核心基线：

- 包含解析、缓冲和逐行文本扫描；
- RSS 是整个 Node.js 子进程的常驻内存，不等同于桌面应用净增内存；
- 不包含浏览器绘制 FPS、Tauri IPC、串口驱动延迟或输入响应；
- GUI FPS、真实 115200/921600 bps 回环和 24 小时稳定性仍需独立验收。

因此，结果只能用于同机、同版本的回归比较，不能直接证明所有性能 NFR 已达标。

## 当前基线

2026-07-27 在 `darwin-arm64`、Node.js `v25.9.0`、xterm.js `6.0.0` 上运行：

| 行数 | 写入耗时 | 吞吐 | 全缓冲搜索 | 峰值 RSS | RSS 增量 | 首行保留 |
| ---: | ---: | ---: | ---: | ---: | ---: | :---: |
| 100,000 | 196.04 ms | 510,092 行/秒 | 39.73 ms | 354.44 MiB | 300.42 MiB | 是 |
| 500,000 | 1,232.17 ms | 405,789 行/秒 | 172.10 ms | 1,180.36 MiB | 1,126.16 MiB | 是 |
| 1,000,000 | 2,534.94 ms | 394,487 行/秒 | 745.38 ms | 2,121.06 MiB | 2,067.47 MiB | 是 |

三档均完整保留预期缓冲区和首行标记。解析、缓冲和扫描速度没有出现数量级退化，但内存
随回滚行数显著增长；百万行仅适合作为用户明确选择的高内存配置。10 万行子进程总 RSS
也高于 NFR-PERF-005 的完整桌面应用 250 MiB 目标，虽然两者统计边界不同，仍应视为
需要 GUI 实测和优化的风险，不能据此关闭该 NFR。

每次升级 xterm.js 或修改终端数据通路时，应在同一台机器重新运行并追加日期、平台、
Node.js、xterm.js 版本和结果。
